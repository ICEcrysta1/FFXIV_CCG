多队列入口是 `Sessions.SimulationEngine`，Python 对应 `InProcessEngine`。一个引擎装载一份职业规则、技能表和配置，多个队列分别持有基础 GCD、战斗状态、事件时间线、策略历史及输出缓存。执行请求只获取所在队列的锁；注册锁只管理创建和释放。同队列事件必须由调用方按时间顺序提交，不同队列可以由不同 Python 线程驱动。该共享关系位于同一进程中。

```python
from scripts.common.inprocess_backend import InProcessEngine

with InProcessEngine("black_mage", capacity=16) as engine:
    # 完整转换保留全部记录；验证可传模型配置中的 history_capacity。
    with engine.create_backend(max_history=None, actual_base_gcd=2.46) as queue:
        queue.submit_action(0.0, "fire_iii")
        observation = queue.observe_at(4.0, format="vector", next_observation_timestamp=4.0)
        counts = queue.statistics()
```

`HistoryRetention` 是统一的记录保留策略：`None` 保留完整记录，整数保留最近 N 条，0 关闭记录；它不控制模拟时长和累计威力。动作与策略记录分别受上限约束，输出时再合并并保留最新 N 条。完整转换仍保存完整 history bank，既不读取模型窗口，也不改变 cache signature。完整历史占用随记录数线性增长，不能承诺无限运行时固定内存；有限窗口模式的常驻记录量有界。

桥接把观测构建和编码放在不获取 GIL 的 C# 调用中，各队列可以并行准备数据；Python 借用托管 `byte[]` 的缓冲区，通过标准库 `pickle.loads` 批量还原现有 dict/list 契约，离开 `memoryview` 后不再持有固定的托管缓冲区。编码器只产生基础值指令，唯一输入是当前程序集生成的 CLR 观测，桥接不读取外部 pickle 文件。Python 容器还原及后续 Python 逻辑仍受 GIL 约束，不能把多线程等同于整条转换流程完全并行。每次观测的可变容器保持独立，只有不可变字符串在单个包内复用。

内部推进与公开 `AdvanceTo` 共用同一个事件内核。阶段 3 的历史和最新状态统一为上一动作后与当前请求快照，按请求身份关联并冻结；wait 的动作后状态来自决策落实时，历史裁剪不丢失已知前序快照。真实动作前后统计与模型状态独立保存。阶段 4 已删除技能绝对时间 `time_seconds`，技能数值特征为 18 维，两段基础状态继续保留时间，共 86 维；本次再加入两段按固定动作顺序保存的绝对二值表，当前黑魔 25 个动作使状态值为 136 维，null/reset 仍为 86 维；在线历史身份从当前请求状态获取时间，并逐字段确认复用。阶段 5 编码顺序为场景、状态、技能交错、最新状态，300 条动作对应 601 个非场景 token，容量单位仍为动作数。当前 canonical 15、桥接 17、checkpoint 输入 22、样本 schema 11、cache v23/转换 v26、部署 25/manifest 16、GRPO rollout 7；字段归一化契约仍为 2。

完整历史 bank 保存原始 FP32 ABS、相邻 DELTA、null 和 reset；当前状态也保存 raw ABS/DELTA，场景保存完整绝对时间。ContextEncoder 在模型外统一进行窗口 gather、ABS 重锚、场景裁剪排序及有符号归一化，再转为模型激活精度。首状态恢复真实 ABS，以 request_state.time_seconds 为原点；基础状态后续所有数值包括布尔差分，技能可用性保持绝对二值，缺失恢复使用字段 ABS reset。时间按 model.time_delta_scale（主线 120 秒）缩放且不 clipping；log 累计威力先求 raw DELTA 再 signed log。模型新增零初始化的 state_reset_proj；超出 C=300 时保留 K=8 条动作并重新累积，真实引擎时间、伤害与 PPG 分母不重置。ONNX 宿主执行同一编码，图只接收已编码的 12 个输入；重锚后 KV prefix 必须重建。

上下文字段声明集中于 context_fields.py；raw batch 的场景使用 scene_abs_values，编码后只保留 scene_vectors。dataset 在读取边界显式映射现有 cache 磁盘场景字段，本次新增技能表必须一次性重建旧产物，后续读取参数调整仍复用同一 raw cache。Normalizer 只提供正式状态编码元数据与技能归一化，不再保留旧状态 normalize/inverse 接口。LiveBatchBuilder 的 history_cursor 通过独立 context_metadata 保存，窗口长度由 history_mask 得出，起点由 cursor−length 得出；GRPO rollout 7 同样独立序列化元数据，并在文件头/manifest 保存唯一输入契约、校验内外动作顺序，旧 rollout 需重新生成。历史消融先按模型 history_capacity/history_reset_keep 选择正式窗口，再按 max_history 保留最近 N 条，消融长度不改变正式重置周期。

输入编码取消各类独立 LayerNorm，在 content 与 role 相加后统一执行一次无参数 RMSNorm，epsilon 为 1e-5；Transformer 主干两处子层归一化及最终读出也统一采用无参数 RMSNorm，epsilon 为 1e-5。普通残差每层先执行 `r*x+a*x0`，再相加 attention 和 FFN 输出；x0 是统一输入 RMSNorm 后的初始 token，同一前向的所有层共用且保留梯度。r、a 按层可学习，主线初始化端点为 r：1.15→1.05、a：0.20→0.05，由 model.yaml 权威保存；Full AttnRes 使用自身独立的深度聚合路径。Q/K 在 RoPE 后逐 head 执行无参数 RMSNorm（`eps=None`），各自乘以保存的 `model.qk_norm_scale`（黑魔 Artzip 当前为 1.2）；KV-cache 只对新 K 归一化一次。

动作读出使用独立无 bias 输出头，初始化按 `action_to_vocab_id` 顺序复制技能 embedding 的动作行，后续独立训练；以 FP32 执行 `s*tanh(logits/s)`，s 由保存的 `model.logit_softcap` 提供，黑魔 Artzip 当前为 15.0。训练、trace、KV-cache、Full AttnRes 与 ONNX 共用动作头和 softcap；ONNX 适配层在 softcap 后将输出恢复为部署目标精度，图内不包含宿主重复惩罚和合法性过滤。checkpoint 恢复已学习的独立头与保存的两种尺度，不从本机 YAML 补默认值。黑魔 Artzip 主线为 6 层、d_model 384、6 个 Q head、1 个 KV head、ff_dim 1536。此次状态差分替换需一次性重建 raw 双 bank cache；后续容量、保留数、时间尺度及随机裁剪变化复用同一 cache。旧共享头、未归一化 Q/K、旧普通相加残差、旧 LayerNorm 主干或旧输入编码的 checkpoint 和部署包拒绝复用，需重新训练、导出；旧技能时间字段或旧状态语义产物仍须重建。

引擎容量耗尽时立即报错，由宿主负责调度待执行任务，不在引擎内部积压请求。`queue.init()` 仅重置该队列，`queue.close()` 释放队列容量，`engine.close()` 关闭全部队列；关闭的句柄永久失效。请求结果在队列锁内连同时间游标一起生成，单队列错误不关闭其他队列。职业规则装配完成后只读，运行数据必须写入传入的 `CombatState`。

训练的 `val_ppg` 仍从所选验证 source 的首个样本初始时刻运行到最后一个 Boss 可选中窗口结束；`history_capacity` 只是输入/记录窗口。`none_ppg` 则按配置的 GCD 数运行。转换 CLI 和训练/VAL 补编译现已共用有界线程调度：每个编译批次只创建一个引擎，`CONVERT_FFLOGS_WORKERS` / `--workers` 同时决定线程数和队列容量，在途任务不超过该值；单文件失败后释放队列并继续处理后续文件，已有有效缓存不启动引擎。验证 PPG、GRPO、普通回放、历史消融和 ONNX 验收共用有界回放调度；模型推理由调用线程执行，PyTorch 可合批，固定 batch=1 的 ONNX 部署契约保持不变。

单条兼容入口已移除：`InProcessBackend` 必须接收已有引擎，`AutoregressiveReplaySession` 必须接收共享引擎和模型后端，`AutoregressiveReplay` 必须接收已有会话。队列/会话只关闭自身资源，不关闭宿主引擎。业务入口统一调用 `run_replays`、`run_rollout_parities` 或 `compile_raw_training_caches`；单条任务也以单元素序列提交。

回放与 parity 报告的动作、逐决策差异和 PPG 按轨迹记录；`backend_metrics`、`reference_metrics` 与 `compared_metrics` 则是生成报告时共享后端的累计快照（`scope=backend_lifetime`）。调用数和最大延迟覆盖后端生命周期，延迟分位数只取最近 4096 次；内存为进程工作集与 PyTorch 设备分配峰值，不能当作单条轨迹的独立用量。
